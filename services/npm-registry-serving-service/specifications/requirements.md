# Metadata cache and publication admission

The registry retains durable package facts and artifacts separately from rebuildable metadata views. Cache retention must not prevent ordinary publication from recovering after heap pressure.

- The configured house and public metadata budgets bound their retained serialized material. Insertion and later representation growth both evict least recently used entries, including a newest entry that cannot fit. A zero budget retains nothing. A response may still serve an oversized view without caching it.
- House view accounting includes admitted fact material, rendered representations and cached search entries. Public accounting includes the received metadata and its cached rendered representations. Strings are measured as UTF-8 bytes. These budgets are retention accounting, not an exact V8 heap or RSS measurement.
- A publication refused by the existing heap-pressure guard releases rebuildable metadata caches before returning the existing 503/Retry-After response. While that same guard reports pressure, new views must not enter those caches.
- The 80 percent V8 guard, bounded publication body, serialized publication, immutable versions, facts and artifacts remain unchanged. Reclamation must not force garbage collection, alter runtime limits, delete durable storage or admit a publication while pressure is reported. Ordinary V8 reclamation determines when the guard clears.

Receiving observes cache eviction, uncached oversized responses, preservation of source metadata and successful ordinary retry after pressure clears. It does not claim that a process restart caused an earlier publication to succeed.

## Each node serves its own registry (P0, Leader 2026-10-29)

Record: `data/records/requirement-records/each-node-serves-its-own-registry.json`.

- N-1: Every node runs its own registry (`bin/serve.mjs`) over its own store; on that node the registry's name resolves to it. No install or publish on a node depends on the Cloudflare Worker's request allowance.
- N-2: No node, Worker or bucket is canonical. A configuration declares `peers` (another node's registry, or a bucket laid out as `<name>/index.json` and `<name>/-/<file>`); a peer is a channel, not a center.
- N-3: A node's store is filled from its peers and its own publications. A house name the store does not hold is received from its peers on first use (and before a publication builds on it); `bin/receive-from-peers.mjs` fills it ahead of use from names or a pnpm lockfile. A version's facts are received whole; its tarball bytes are received for the versions a lockfile names (or `--all-bytes`) and otherwise when first requested, so a node's disk holds the bytes it uses.
- N-4: Receiving is by content address: a tarball is kept only if its bytes are its advertised integrity and shasum, under the NI address of its own bytes. A held version is never replaced; other bytes for it from a peer are a reported divergence.
- N-5: A publish on a node writes only that node's store and builds on the history its peers hold.
- N-6: Public names are fetched from the uplink on first use and their tarballs kept on disk (`publicTarballs: "proxy"`, `cachePublicTarballs: true`).
- N-7: LAGOON provides the unit; the plain user unit is transitional.
- N-8: Every node applies the canonical Worker's identity conservation (`src/registry-identity-conservation.mjs`, R2-10, R2-13) from the same record: a configuration's `identityConservation` is the typed policy or the path of a record holding it, and by default the repository's `data/records/registry-identity-conservation-records/registry-identity-conservation.json` for that record's origin. A quarantined version, a tag naming it and its archive refuse 409 with the Worker's body; the full and install packuments leave them out and carry `x-561-registry-conflicts`; publication and tagging of a quarantined version refuse 409; peer receiving never receives one or a tag naming it. A node may hold either recorded identity; any other stored identity is drift and fails closed. Nothing stored is changed.

- N-9: Node search SHALL select its version, description, keywords, publisher and maintainers only from the identity-checked versions and tags in the served packument. If no version remains, the package SHALL be omitted before ranking, pagination and totals. Search SHALL preserve stored facts and use the existing fail-closed refusal for identity drift. Cached search entries SHALL be invalidated when the package journal changes. This node projection does not enable canonical R2 catalogue search.
