# Bounded rebuildable metadata

The existing weighted LRU is shared by house views and public packuments. Its previous insertion protected the newly inserted key even when that entry exceeded the budget, and representation growth increased its weight without eviction. The correction uses one trim operation after every increase and permits every key to leave. The private cache module exposes no registry protocol or new runtime operation.

House views weigh their actual serialized admitted facts instead of a fixed per-row guess. Rendered bodies and search entries add their UTF-8 serialized size. Public rendered bodies live on the same bounded entry as their packument rather than in a separately uncharged weak-map side cache. In-flight callers may finish using a view evicted during rendering; eviction controls retained cache ownership and does not interrupt responses.

The existing publication guard clears both rebuildable caches on a pressure refusal. Cache admission also consults the same guard so concurrent reads do not refill them while pressure persists. The registry continues to refuse the publication before reading its body and retains Retry-After. No explicit GC, alternate pressure provider, new host service or storage mutation is introduced.

Tests use the existing pressure port and real registry handler/store. They verify observable upstream refetch and uncached service, durable publication refusal/retry, and weighted-LRU eviction including growth and oversized/zero-budget cases. They make no assertion about the timing of V8 major collection.

## Conflicting identities and native-only reservations

The original R2 receiver consumes typed restrictive observations from its operator configuration. Each conflict retains independently received native and canonical R2 manifest fingerprints, source commits, archive URLs/integrities and an evidence commitment. Each reservation identifies one already-observed native-only product. JSON manifest fingerprints use the existing Data json-engineering-services-section RFC8785 implementation, preserving authored text and ignoring object key order. The configuration supplies restrictions, never a publisher permission or capacity waiver.

An absent legacy source is represented explicitly as null only in conflict observations; the entire manifest fingerprint still binds the absence and all authored fields. Reservations require a known source commit. The Worker adapter can receive the same typed policy through separate conflict and reservation array bindings when their combined representation exceeds a platform variable limit. Both arrays must be present and an embedded policy must be absent; the original generic validator remains authoritative.

The receiver keeps raw storage receiving separate from its served/admission projection. Only the raw object and its raw R2 ETag enter publication CAS. A projection removes quarantined versions, tags and time entries from responses and adds conflict evidence; its ETag commits those served bytes. Exact conflicted version/tag/archive reads return409, including HEAD. The shared original dependency gate reads the same projection. Unaffected publication merges raw originals so a projection cannot delete quarantine data. Reserved exact products still pass every ordinary auth, wire, static-gate and conditional storage check.

Automatic publication remains held at its existing original ingress boundary during reconciliation. Actual sender quiescence and queued legacy custody precede the fresh original inventory delta. Existing native products are received byte for byte through the original prepared port; neither a new source build nor a replacement version repairs an immutable identity conflict. Both conflicting products remain retained, and normal publication reopens only after independently received conservation.

## Prepared npm decoding

`src/prepared-publication.mjs`, exported as `./prepared-publication`, is the same pure decoder consumed by native and R2 receiving. It retains optional repository and arbitrary authored manifest fields without interpreting them as GitHub source authority. The existing source publisher owns its own repository/source qualifications; removing that interpretation from decoding grants no publisher permission. Receiving includes an npm archive carrying a semantic data document, an absent repository, a non-GitHub repository, exact byte/field preservation and malformed identity/integrity/attachment refusals. It starts no server or installation.
